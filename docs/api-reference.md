# REST API Reference — Agent Assurance Laboratory

All endpoints require:
- Header `X-Correlation-ID: <uuid>` (propagated across all traces and responses)
- Scoped Bearer authentication in production (`Authorization: Bearer <token>`)

Standard Error Envelope:
```json
{
  "code": "BAD_REQUEST",
  "message": "Explicit authorisation must be confirmed before registering an agent.",
  "correlation_id": "web-1729800000"
}
```

---

## 1. System & Health

### `GET /health`
Liveness probe. Returns `{"status": "ok", "version": "1.0.0"}`.

### `GET /ready`
Readiness probe. Verifies database and plan seeding readiness.

### `GET /v1/kill-switch`
Inspect operational kill switch status.

### `POST /v1/kill-switch`
Toggle operational emergency kill switch (Platform Admin only).
- **Request**: `{"enabled": true, "tenant_id": null, "reason": "Incident drill"}`

---

## 2. Agents & Adapters

### `POST /v1/agents`
Register an authorized agent target.
- **Request**:
```json
{
  "name": "Customer Support Agent",
  "description": "Tier 1 chatbot",
  "adapter_type": "http",
  "endpoint_url": "https://agent.internal/v1/run",
  "allowed_hosts": ["agent.internal"],
  "auth_env_var": "AGENT_TOKEN",
  "timeout_seconds": 15.0,
  "authorised": true,
  "scope_description": "FAQ search only"
}
```
- **Response**: `201 Created` with `AgentView` (raw credentials omitted).

### `GET /v1/agents`
List all registered agents for the tenant.

### `GET /v1/agents/{agent_id}`
Retrieve single agent manifest.

---

## 3. Assessments

### `POST /v1/assessments`
Create a scoped assessment project.
- **Request**:
```json
{
  "title": "Q4 Release Assurance",
  "agent_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "scope": "Evaluate tool permission boundaries and prompt injection resilience."
}
```
- **Response**: `201 Created` with `Assessment` entity including computed `scope_hash`.

### `GET /v1/assessments`
List all assessment projects for the tenant.

### `GET /v1/assessments/{assessment_id}`
Get assessment project details.

---

## 4. Runs & Evaluation

### `POST /v1/assessments/{assessment_id}/runs`
Launch an idempotent assurance run.
- **Headers**:
  - `Idempotency-Key: <unique-key>`
  - `X-Correlation-ID: <uuid>`
- **Request**:
```json
{
  "scenario_pack": "core-v1",
  "scenarios": [
    "allowed_tool_smoke_v1",
    "prompt_injection_boundary_v1",
    "approval_gate_v1",
    "retry_idempotency_v1"
  ],
  "model_budget_tokens": 5000
}
```
- **Response**: `202 Accepted` with `Run` entity, including `results` and `summary` (`PASS`, `FAIL`, `INCONCLUSIVE`).

### `GET /v1/runs`
List runs, optionally filtered by `?assessment_id=...`.

### `GET /v1/runs/{run_id}`
Get details, progress, and scenario outcomes for a run.

### `GET /v1/runs/{run_id}/findings`
Get security findings auto-generated by the run.

---

## 5. Findings & Human Review

### `GET /v1/findings`
List all security and policy findings for the tenant.

### `GET /v1/findings/{finding_id}`
Get finding details, evidence trace reference, and review history.

### `POST /v1/findings/{finding_id}/reviews`
Submit a reviewer disposition or override.
- **Request**:
```json
{
  "decision": "false_positive",
  "reason": "Test canary injected by deliberate evaluation design for sandbox verification."
}
```
- **Response**: `200 OK` with `Review` audit record. Automated verdict remains preserved.

### `GET /v1/findings/{finding_id}/reviews`
Get complete audit trail of reviews for a finding.

---

## 6. Reports & Regression

### `POST /v1/runs/{run_id}/report`
Generate an immutable assessment report artifact.
- **Request**: `{"format": "json"}` or `{"format": "pdf"}`
- **Response**: `202 Accepted` with `ReportArtifact`.

### `GET /v1/reports/{artifact_id}`
Retrieve report artifact metadata and content.

### `GET /v1/reports/{artifact_id}/download`
Download report as an attachment (`.json` or `.txt` formatted printable report).

### `GET /v1/runs/{run_id}/compare/{other_run_id}`
Compare two runs scenario-by-scenario. Returns `RegressionComparison` with deltas, new failures, and resolved issues.

## 7. Scenarios & Catalog

### `GET /v1/scenarios`
List all 12 versioned scenarios with descriptions, categories, and severity tags.

### `GET /v1/scenarios/{scenario_id}`
Retrieve specific scenario specification and assertions.
